# Changelog

Every runtime build gets a number (`pcNNN`). Only builds that changed something visible are listed; the bug details
are in [FINDINGS](FINDINGS.md) and [KNOWN_ISSUES](KNOWN_ISSUES.md).

## 11 November 2026 — 1.0.1

| Build | What changed | Result |
|---|---|---|
| bridge | **Windows exit at start (`0xC0000409`) found and fixed.** Reproduced on a clean GitHub Windows runner (Vulkan via lavapipe, D3D11): the CPU, pump and texture-replacement worker threads were still joinable `std::thread`s when the DLL unloaded, so the C++ runtime called `abort()`. Threads are detached and the process ends with `TerminateProcess` after flushing. PCSX2 data in `%APPDATA%\ts2-recomp\pcsx2` instead of `Documents\PCSX2`. `build\bridge.log`: every start step plus module+offset of any crash | runner: Vulkan, Vulkan with raylib first, German menu, D3D11 – all exit 0; package under Wine: setup, Siberia to the sniper zoom, 59.94 FPS |
| bridge | PCSX2 messages "patches.zip" and "Controller 1 has no input bindings" removed during the first seconds (they do not apply to the port) | Linux and Windows CI |
| `pc125`–`pc129` | **sniper scope in 16:9:** part of the scope frame was classed as a screen copy (texture base inside the render target although the primitive is untextured) and was not squeezed while the rest was – doubled frame and light stripes. Untextured sprites (crosshair lines, health bars, scope shading) are now treated as 2D; `PRMODECONT`/`PRMODE` respected; vertices on the screen edge stay on the edge | zoom frame, crosshair and bars line up; 4:3 unchanged |
| `pc130`–`pc134` | **HUD at the 16:9 edges by default** (`TS2_HUD_RAND=0` for the old centred layout). The 2D packets of a frame are merged into blocks; in the next frame a block moves to the screen edge only if it is narrow and lies in the left/right third – ammo, timers and counters move, multi-packet texts stay together. Not in menus, loading screens (no 3D scene) or while the scope is up; full-width untextured strips (buffer clears) and edge strips (split-screen frame) are never squeezed | all 10 story levels, menus, loading screens, story co-op split screen and the scope checked in 16:9 |
| `pc139`–`pc143` + launcher | **Windows on real PCs:** setup works without OpenGL (raylib 5.5 called OpenGL after a failed window; the runtime now probes first), the graphics hand-over file moved from `/tmp` (= `C:\tmp`, missing on Windows) to the system temp folder, exit code 3 when the graphics cannot start so the launcher can switch renderer; the launcher starts with Direct3D 11 (Vulkan as fallback) | Windows VM: full setup; tester PC (RTX 3060 Ti): story level 1 played through, 59.9 FPS, ~30 min without errors |
| packages | Windows FFmpeg DLLs optional (`TS2_WIN_FFMPEG=0` saves ~55 MB, without F8 recording); default unchanged | |
